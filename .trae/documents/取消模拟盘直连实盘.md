# 取消模拟盘，直接为实盘

## Context（背景）
系统当前有「模拟盘 / 实盘」两套视图与运行模式（/live/sim 与 /live/real），且 app 启动时自动开启模拟盘引擎（dry_run=True）用于展示与验证。用户已明确：**彻底删除模拟盘功能，让系统直接以实盘运行，并开启自动实盘下单**（监控股满足买入规则 → 直接真实下单，无需审批）。

关键前提：`LiveSimRunner`（lib/live_simulator.py）是**模拟与实盘共用的引擎 runner**，scheduler.job_start_engine 就是用它以 `dry_run=False` 跑实盘主循环。因此**不能整类删除 LiveSimRunner**，只能：
1. 删除 dry_run 模拟路径（模拟撮合）
2. 删除 sim 专属 REST 端点、sim 视图、app 启动时自动开模拟盘的逻辑
3. 引擎固定走实盘（dry_run 恒为 False），并保留自动下单（trade.enabled 已为 true）

## 变更清单

### 1. 数据来源与「默认视图」改为实盘
- **app.py**
  - 删除 `/live/sim` 页面路由；`/live` 直接渲染实盘视图（不再 302 到 /live/sim）。
  - `/live/real` 可保留为别名或直接由 `/live` 承载。
  - 删除 `_auto_start_sim()` 及 `main()` 中对它的调用（不再在 web 进程自动开模拟盘引擎；实盘引擎由 scheduler 驱动，避免双引擎重复下单）。

### 2. REST 端点：删除模拟盘专属接口
- **routes/live.py**
  - 删除：`/sim/status`、`/sim/start`、`/sim/stop`、`/sim/trial_run`、`/sim/reset_positions`、`/sim/clear_history`。
  - 保留：`/state`、`/control`、`/status`、`/watch_merge`、`/watch_pool`、`/strategies/*`、`/daily_watch`、`/stock/bind`、`/ping`。
  - 删除对 `LiveSimRunner` 模拟语义中有害的初始化？不——`_SIM = LiveSimRunner()` 仍由 scheduler 场景用，但 route 模块内不再需要其 sim 端点；若不再引用则移除该 import/singleton。

### 3. 前端：去掉视图切换，只保留实盘仪表盘
- **templates/live.html**
  - 删除顶部「模拟盘 / 实盘」视图切换 tab（289-310），`viewMode` 恒为 `real`。
  - 把原 sim 视图下的核心面板 **实时持仓、买入记录、监控池** 移出 `x-show="viewMode==='sim'"` 容器，改为始终渲染（这些正是用户要的结果：实时持仓/买入记录/当日监控），并删除 real 视图另一套重复布局（773+），只保留一套集成面板。
  - 删除「启动模拟盘 / 停止模拟盘 / 试算一轮 / 重置持仓」等按钮及其 JS 处理器（start_sim/stop_sim/trial_run/reset_positions/clear_history 相关）。
  - `refresh()` 中删除 `this.sim = .../api/live/sim/status` 拉取；面板数据仅依赖 `/state` 与 `/api/live/daily_watch`。
  - 事件面板占位文案（"启动模拟盘后…"）改为实盘语境。

### 4. 引擎：去掉 dry_run 模拟分支，固定实盘
- **live_trading/live_loop.py**
  - `_handle_signal`：删除 `if self.dry_run:`（apply_fill + return 的模拟撮合分支），始终走 MiniQMTTraderV2 真实下单路径。
  - **保留** `apply_fill()` 用于实盘成交后回填 `state.positions`（实时持仓/监控池已买入依赖它），实盘提交成功后继续调用。
  - 简化状态：`self.dry_run` 恒为 False；`control.dry_run` 相关写入可移除或置 False。
- **lib/live_simulator.py**
  - 保留 `LiveSimRunner`（scheduler 实盘引擎依赖），但 `start()` 不再由 mock_positions 播种初始持仓（实盘持仓应从券商拉取）。模拟相关的 mock 播种/`reset_positions` 逻辑移除或置空。
- **scheduler.py**
  - `job_start_engine`：摘掉 `TRADER_DRY_RUN` 开关，恒 `dry_run=False` 启动实盘引擎（09:00 启 / 14:55 停，保持调度）。

### 5. 配置与数据
- `.env`：`TRADER_DRY_RUN` 维持/置为 0（实盘）；保留 `TRADER_BACKEND=bigqmt`。
- `config/strategy_selection.yaml`：保留 `trade.enabled: true`（自动实盘下单）。确认 buy 规则（days=1 次日买）符合预期，若需当日买再调 days=0。
- 删除/停用 `config/mock_positions.yaml`（仅模拟盘播种用）。

## 复用的既有能力
- `apply_fill()`（live_loop）：实盘成交后回填内存持仓，实时持仓/监控池已买入据此显示。
- `daily_watch` 端点（routes/live.py）：当日选股池 + 是否已买入 + 名称映射，供实盘视图「监控池」使用。
- scheduler `job_start_engine` / `job_stop_engine`：实盘引擎单一驱动源（避免双引擎重复下单）。

## 验证
1. `python -m py_compile` 所有改动文件（app.py、routes/live.py、live_loop.py、live_simulator.py、scheduler.py、live.html 语法由模板服务端渲染自动验证）。
2. 重启 app.py：`GET /` 与 `GET /live` 应直接进入实盘视图，无模拟盘 tab、无启动模拟盘按钮。
3. `GET /api/live/sim/status` 应 404；`GET /api/live/daily_watch`、`/api/live/state` 仍 200。
4. 确认无 `if self.dry_run` 模拟撮合残留（grep）。
5. 实盘下单链路：确认 live_loop 仅在实盘路径回调 MiniQMTTraderV2（佐证 bigqmt 桥/账户已就绪）。
6. 启动 scheduler engine job 验证 09:00 能以 dry_run=False 启动引擎（非交易时段可手工 `python scheduler.py --job engine` 观察日志确认 REAL 模式）。
