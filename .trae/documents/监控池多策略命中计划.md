# 调整监控池逻辑：策略自动选股入监控池 + 多策略命中计数

## Context（背景/动机）

当前监控池（`config/watch_pool.yaml`）与选股池（`trade_selection_pool`）是**两套独立机制**：
- 选股池已按 `(strategy, stock_code)` 记录每个策略的当日选中股，交易主循环在 per_strategy_mode 下**直接读选股池**取信号目标（`iter_strategy_signal_targets`），**不依赖 watch_pool.yaml**。
- watch_pool.yaml 目前只被：旧模式/兜底的 `merge_watch_codes` 使用，以及 dragon 龙头战法、live.py 手动绑定、手动编辑写入。

**用户需求**：
1. 监控池与选股池打通——**策略自动（定时选股 cron 触发）选出的股票自动入监控池**。
2. **多策略都选中同一只股票时，提示命中次数**（1 个策略命中=1 次，2 个策略=2 次……）。
3. **手动发起选股**（用户点"立即选股"）选出的股票**不入监控池**。
4. 命中次数**实时计算**（每次选股完成即可查，刷新即更新）。

**目的**：让监控池真实反映"当日被策略自动选中"的股票，并让用户能直观看到一只股票同时被几个策略命中的强度，同时把手动选股与自动选股在监控池层面解耦。

## 核心设计决策

- **"入/不入监控池"以选股触发方式区分**：
  - 自动定时选股（策略各自 schedule cron，走 `run_one_selection(name, trigger="cron")`）→ **入选后同步并入 watch_pool.yaml**（入监控池）。
  - 手动发起选股（/api/strategy/run → `run_all_selection(trigger="manual", selected_at=...)`）→ **只写选股池，不写 watch_pool.yaml**（不入监控池）。
- **命中次数**：从 `trade_selection_pool` 实时聚合——同一 `trade_date` 下，`COUNT(DISTINCT strategy)` where `stock_code=X`，即 X 被几个策略选中（命中几次）。无需新表、天然实时。
- cache/兜底 watch_pool 用法保持不变（dragon 等手动能力仍可用，但监控池主体由选股池驱动）。

## 涉及文件与改动点

### 1. `lib/selection_store.py` — 增加监控池同步与命中聚合
- 新增 `sync_pool_to_watch_pool(codes: List[str]) -> List[str]`：
  将一份选股 code 列表**并入** `config/watch_pool.yaml`（去重、保留已有），复用现有 `load_watch_pool`/`save_watch_pool` 语义（但这两个函数在 `live_simulator.py`，注意调用方向避免循环依赖——将同步逻辑放在 `selection_store.py` 内以 pymysql 读、yaml 写，或复用 live_simulator.load/save）。返回新增的 code。
  - 为避免循环 import，建议：`selection_store.py` 内部直接读写 watch_pool.yaml 路径（`PROJECT_ROOT/config/watch_pool.yaml`），不依赖 live_simulator。
- 新增 `count_strategy_hits(trade_date: str) -> Dict[str, int]`：
  返回 `{stock_code: hit_count}`，hit_count = 该 code 在该 trade_date 下出现在几个不同 strategy 的行数（`SELECT stock_code, COUNT(DISTINCT strategy) FROM trade_selection_pool WHERE trade_date=%s GROUP BY stock_code`）。

### 2. `lib/strategy_runner.py` — 区分 trigger 决定是否入监控池
- `run_all_selection(trigger=...)`：当 `trigger == "manual"` 时（用户手动点选股），**不**调用监控池同步；其他 trigger（cron）同步。
  - 在写库 `replace_selection_pool_daily` 之后，收集本次各策略最终 `per_strategy` 的全部 code 并集，调用 `sync_pool_to_watch_pool(codes)`。
- `run_one_selection(name, trigger="cron")`（策略各自定时）——**总是**入监控池（它在 app.py 定时调度里以 `trigger="cron"` 调用；手动可走 run_all_selection 的 manual 分支）。注意：确认 `run_one_selection` 是否也被手动调用；若被手动调用需同样区分 trigger。
  - 在写库后收集该策略选出的 code，调用 `sync_pool_to_watch_pool`。

### 3. `lib/selection_store.py` — `replace_selection_pool_daily` 可接收/返回代码并集
- 微调：让选股写库后能拿到本次全部 code（或由 caller 从 `per_strategy` 汇总，不改动该函数签名）。

### 4. `routes/pool_page.py` — 接口返回命中次数
- `GET /api/pool/list`：新增对当前 `trade_date` 调 `count_strategy_hits`，为每行注入 `hit_count`（该股票被几个策略命中），并在返回中加入 `hit_count` 字段；同时提供 `summary` 或单独字段。
- 保持向后兼容：不破坏现有字段（新增字段即可）。

### 5. `routes/strategy_page.py` — 手动触发不入池
- `/run` 保持 `trigger="manual"` → 由 `run_all_selection` 内据此跳过监控池同步（无需改路由，逻辑在 runner）。

### 6. `templates/pool.html` — 展示命中次数
- 表格新增"命中次数"列（或在现有"入选策略"列旁），显示每行 hit_count；命中 >1 次时高亮提示（例如 badge 显示 `命中 N 次`）。
- 后端把每行 hit_count 传入 flat rows。

### 7. `lib/live_simulator.py`（如必要）— 确认 merge 不再因手动 watch_pool 项影响
- 若 "手动不入池" 要求严格，需确认 dragon /bind、live /stock/bind 写入 watch_pool 的行为不被误判为"自动"。此项**默认不做改动**（保留现有手动能力），除非用户要求。

## 数据流（改动后）

```
策略定时调度 (app.py cron, trigger="cron")
   → run_one_selection / run_all_selection
      → run_strategy_selection → rows
      → replace_selection_pool_daily(per_strategy, trade_date)   [写选股池]
      → sync_pool_to_watch_pool(并集 codes)                       [自动入监控池 watch_pool.yaml]
      → 写 live_state.json + 命中计数由选股池实时聚合             [命中次数]

手动点"立即选股" (/api/strategy/run, trigger="manual")
   → run_all_selection(trigger="manual")
      → 写选股池 (同)                                             [写选股池]
      → 跳过 sync_pool_to_watch_pool                              [不入监控池]

GET /api/pool/list
   → query_selection_pool + count_strategy_hits(trade_date)
      → 每行 hit_count = 该股被几个策略选中
```

## 验证方式（Verification）

1. **命中计数 SQL**：手动执行
   `SELECT stock_code, COUNT(DISTINCT strategy) FROM trade_selection_pool WHERE trade_date=<当日> GROUP BY stock_code`
   核对与预期一致。
2. **自动入选池**：调用一次 `run_one_selection("weak_to_strong", trigger="cron")`（模拟定时），确认 watch_pool.yaml 新增该策略选中 code。
3. **手动不入池**：调用 `POST /api/strategy/run`（trigger=manual），确认选股池写入但 watch_pool.yaml **不新增**。
4. **接口/前端**：`GET /api/pool/list` 返回每行 `hit_count`；若某股被 ≥2 策略选中，hit_count≥2 且前端显示命中次数高亮。
5. 回归：确认 `iter_strategy_signal_targets` 仍从选股池取目标（不受 watch_pool 同步影响）；`merge_watch_codes`/dragon 手动能力不受破坏。

## 风险与注意

- **循环依赖**：`selection_store` 与 `live_simulator` 可能在 watch_pool 读写上有循环 import。隔离方案：selection_store 内直接按路径读写 yaml，不 import live_simulator。
- **trigger 语义确认**：需在实施时核实 `run_one_selection` 是否会被手动路径调用，若有则加 trigger 区分。
- **命中次数口径**：以 `trade_date`（选股日）为准；历史回放（selected_at 为过去日期）时，命中聚合按该 trade_date 统计，需保持一致。
