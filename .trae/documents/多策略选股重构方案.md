# 多策略并行选股重构方案

## Context（背景与目标）
当前选股/实盘的核心是「股票→策略路由」模型：`config/strategies.yaml` 用 `{default, per_stock}` 把每只股票路由到一个策略，其中 `default` 是未绑定股票的兜底策略；选股结果只写 `outputs/live_state.json`，**无数据库持久化**（`wucai_trade` 库目前只有 `trade_stock_daily` / `trade_stock_minute` 两个表）。

用户要求结构性重构为「策略→股票清单」模型：
1. **多策略并行**，各自独立启停，各自配置自己的选股条件，**无缺省策略概念（删除 default 兜底）**。
2. 每只策略**从全市场**（数据库已有日线的 A 股）按自身条件选出自己的股票，生成**每策略选股池**。
3. 选股池**只记录候选（不自动生成买卖信号）**；买入/卖出由各策略在其候选+持仓上**独立判断**，**共享总资金/独立持仓记账**，策略间互不影响。
4. 每策略选股池**存储到数据库表**，网页端按策略分组展示。

## 现状要点
- 策略=单只股票评估器：`StrategyMeta.evaluator(code, market, capital)->{side,strategy,reason}`，注册于 `lib/strategy_registry.py`；`StrategyRouter`（L1044-1077）做 `per_stock[code] 或 default` 路由。所有现注册策略**没有原生全市场选股器**。
- `lib/strategy_runner.py#run_all_selection(trigger)`：合并监控池→按路由逐股评估→写 `live_state.json["selection"]`。
- 实盘 `live_trading/live_loop.py#run_once()` 遍历 watch_stocks 调 `signal_evaluator`；`_handle_signal` 按单一 `self.capital` 定仓；持仓是 `live_state.json` 扁平列表。
- 数据库层复用 `lib/backtest_data.py#_db_config()`（读 `.env` 的 `WUCAI_SQL_*`，pymysql）。

## 用户已确认的设计决策
- 选股范围：**全市场按条件选**。
- 独立买卖粒度：**共享总资金 / 每策略独立持仓**。
- 模型：**彻底重构**路由→策略模型（删除 default）。

## 实施方案

### 1) 新配置 `config/strategy_selection.yaml`
每策略一个条目，可独立启用/关闭，含选股条件：
```yaml
universe:
  source: mysql            # mysql | qmt | code_list
strategies:
  - name: multi_factor_top
    label: 多因子精选
    enabled: true
    universe: all_a        # all_a(有日K全部A股) | code_list
    code_list: []          # universe=code_list 时用
    lookback_days: 120
    top_n: 20
    selection:
      mode: registry_scan  # registry_scan=有原生选股器 | generic_filter=声明式过滤 | code_list=码表
      filters:             # 声明式全市场过滤，缺失元数据字段运行时跳过并告警
        min_price: null
        max_price: null
        min_change_pct: null
        max_change_pct: 9.9
        min_turnover: null   # 需股本/市值元数据，否则跳过
        max_turnover: null
        min_market_cap: null # 同上
        max_market_cap: null
        min_vol_ratio: null
      sort_by: score        # generic_filter 用 amount 兜底
      sort_desc: true
```
- **selector 能力**：`StrategyMeta` 增可选 `selector(snapshot_df, market, params, capital)->pandas.Series 得分`。`multi_factor_top`/`dragon_picker` 提供原生 `registry_scan`；其余信号类策略（`macd_*`、`ma20_hold`、`grid_classic` 等）用 `generic_filter`，选股阶段**运行声明式过滤，不跑 evaluator**；evaluator 仅在买卖阶段对各自池+持仓调用。ETF 等不在 all_a 的用 `universe: code_list`。

### 2) 选股引擎（`lib/strategy_runner.py` 重写 + 新 `lib/selection_engine.py`）
- 保留公共入口 `run_all_selection(trigger)`、`get_selection_state()`（路由/app 定时不动）。
- `load_selection_config()` / `enabled_strategy_instances()`：读新 YAML。
- `UniverseSnapshot` + `build_universe_snapshot()`：**批量 SQL 一次性拉全市场**（`SELECT DISTINCT stock_code FROM trade_stock_daily` ≈5218 只 + 近 N 日 OHLCV/amount），派生 pct_change / vol_ratio / amount / turnover / market_cap；**禁止逐股 load_daily_kline**（否则太慢）。复用 `clear_kline_cache` 强制刷新。
- `run_strategy_selection(inst, snapshot, capital)`：按 mode 选股 → `top_n`。
- `run_all_selection`：遍历启用策略，各自选股→**写库**→写 `live_state.json["selection"]`（新增 `per_strategy` 全量候选、`by_strategy` 各策略概要）。

### 3) 数据库层（新 `lib/selection_store.py`，复用 `_db_config`）
- DDL（`ensure_tables()`，幂等，app 启动调）：
  - `trade_selection_pool`：`id, strategy, stock_code, trade_date, rank_no, score, reason, name, created_at, updated_at`，`UNIQUE(strategy, stock_code)`（项目幂等惯例），`KEY(strategy, trade_date)`。
  - `trade_strategy_position`（每策略独立持仓）：`id, strategy, stock_code, name, volume, cost, cur_price, pnl, pnl_pct, updated_at`，`UNIQUE(strategy, stock_code)`。
- 函数：`replace_selection_pool_daily(per_strategy, trade_date)`（事务：删当日不在榜旧行+`INSERT...ON DUPLICATE KEY UPDATE`，使表始终=最近一次各策略候选池）、`query_selection_pool`、`upsert/increment_strategy_position`、`query_strategy_positions`。
- 元数据可选增强：给 `trade_stock_basic` 加 `float_shares/total_mv/float_mv` 列用于换手率/市值过滤；未填则该过滤字段运行时跳过并告警（换手率/市值不可从日K单列安全推导）。

### 4) 买卖独立（`live_trading/live_loop.py`、`lib/live_simulator.py`）
- `run_once()` 步骤4改为**按策略**遍历：每策略 `query_selection_pool(strategy)` + `query_strategy_positions(strategy)` 并集→只对**自己的**代码调 `meta.evaluator`，signal 带 `strategy` 标签。无 default 兜底。
- `LiveSimRunner.start()` 不再构造单个 `StrategyRouter`（`signal_evaluator=None`，由循环驱动），`trial_run` 同步改。
- `_handle_signal`：定仓仍按 `self.capital*10%`，但**加总各策略已投成本 ≤ capital** 的聚合上限；成交后 `increment_position(strategy, code, side, qty, price, capital)` 更新 `trade_strategy_position`。
- 状态归属：`trade_strategy_position`（DB）为每策略持仓唯一事实源；`live_state.json` 保留聚合 `positions`（每行带 `strategy`）+ `selection.per_strategy`（池展示），保证 5s 轮询面板兼容。

### 5) 网页 API / 池展示
- `routes/strategy_page.py`：`/list`、`/config` 改读新 YAML，`enabled` 按实例，**移除 default**；`/run` 不变。
- `routes/pool_page.py` `/pool/list`：改**按策略分组**返回 `groups[]`（`strategy/label/enabled/size/rows`），rows 来自 `query_selection_pool`，side 文案=「候选」，移除 `default/is_default/per_stock` 逻辑。
- `routes/live.py`：`/strategies/config` GET/POST 改新结构；`/stock/bind`、`/stock/unbind` 从写 `per_stock` 改为往对应策略实例 `code_list`（或 `watch_pool.yaml`）追加，不再写 `per_stock`。
- 前端依赖：`templates/live.html`、`strategy.html`、`pool.html` 及提交 `{default, per_stock}` 的 JS 需同批更新（处于范围，已标注）。

### 6) `app.py` 调度
- `run_all_selection(trigger="cron")` 名称/签名不变 → 定时 09:25 / 14:35 无需改逻辑。
- 启动时 `ensure_tables()`（在 `_start_selection_scheduler` 内）。

### 7) 迁移 / 兼容
- `lib/live_simulator.py` 增 `migrate_strategy_config()`：新 YAML 缺失且旧 `per_stock` 非空时，合成一个 `{enabled:false, universe:code_list, code_list:old codes}` 实例保留旧绑定；**default 直接丢弃**。
- `merge_watch_codes()` 并入新配置实例的 `code_list`。
- `load_strategy_config()/save_strategy_config()` 保留为薄 shim（过渡期不崩），过渡后统一指向新 loader。
- 所有读取 `cfg["default"]` 的决策点删除（`live_simulator` 种子/调用点、`pool_page`、`live.py`、`strategy_runner` 路由构建、`trial_run`）。

## 新增/修改文件清单
- 新增：`config/strategy_selection.yaml`、`lib/selection_store.py`、`lib/selection_engine.py`。
- 修改：`lib/strategy_runner.py`、`lib/strategy_registry.py`（加 selector）、`lib/live_simulator.py`、`live_trading/live_loop.py`、`routes/strategy_page.py`、`routes/pool_page.py`、`routes/live.py`、`app.py`，以及前端模板（`templates/*.html`）。

## 验证
1. `load_selection_config()/enabled_strategy_instances()` 正常解析（先放 1–2 个 `generic_filter` 启用实例）。
2. `ensure_tables()` → `SHOW CREATE TABLE trade_selection_pool` 存在。
3. `run_all_selection(trigger="manual")` → ok:True、每策略 `total>0`；DB 查到各策略行；重跑 idempotent 无重复。
4. `POST /api/strategy/run` 返回同样摘要；`GET /api/strategy/list` 无 `default`；`GET /api/pool/list` 返回 `groups[]`，side=候选。
5. 买卖独立：两个策略在重叠股票上各产生买入，`trade_strategy_position` 分别记账，A 不影响 B；聚合持仓成本 ≤ capital。
6. 定时任务注册正常（`ensure_tables()` 后）。
